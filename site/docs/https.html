前面加 HTTPS

向他人提供访问时，在服务器前面加一层 HTTPS 反向代理。成员用 https://log.example.com 这种地址。除了浏览器承认的本机地址，不要用明文 HTTP 登录门户或后台。

服务器进程继续只听本机，例如 127.0.0.1:3000。对外的 443 由 Caddy、Nginx 或其他代理来做证书。

可信代理

只有一层可信代理时，在 .env 里写：

TRUST_PROXY=1

或者在管理后台「服务器设置 → 可信代理层数」填 1。后台保存的值优先于 .env。两种都要在改完后重启进程。Docker 是 docker compose up -d --force-recreate server，不是只改文件。

不要在 Node 端口可被直接访问时把 TRUST_PROXY 设为 true。填实际的层数。端口继续只绑在本机，或放在防火墙后面。

转发路径

至少把这些转到这台服务器：

  • /api：登录、注册、协作接口。
  • /ws：协作的实时连接。要允许 HTTP/1.1 的 WebSocket Upgrade。没开 Upgrade 时，页面能开，实时内容不会更新。
  • /live：Live Share 页面。
  • 用了网页客户端时，再加上 /client/ 和 /connect。
  • 公开归档如果做了根路径别名，那个别名路径也要原样转发，不能被其他站点规则拦截。

示例在服务端仓库的 deploy/nginx-openlogtool.conf.example。按实际域名修改 server_name 和证书路径。

Live Share 持续重连

在浏览器的网络面板里看 /ws/public：

  • 403：通常是 TRUST_PROXY、Host 或 X-Forwarded-Proto。代理要带上原始的 Host，以及 X-Forwarded-Proto https。层数要和真实的代理层数一致。
  • 404、200 或 502：通常是未把 /ws 转到 Node，或没打开 Upgrade。普通网页的反代规则不够。

完成后

用域名打开 https://log.example.com/login。地址栏应显示安全连接，而不是证书错误。登录后可以打开好友页。已发布的 Live Share 可在其他浏览器打开，且不会停留在正在重连。
