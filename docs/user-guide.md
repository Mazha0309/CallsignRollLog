# Callsign Roll Log 使用手册

左侧为目录，右侧为当前页说明。按钮名称与软件界面一致。仅在本机记录时不需要账号。共同记录时，双方须在**同一台**服务器上分别注册。账号不能跨服务器使用。

## 四个页面

宽屏显示在左侧，窄屏显示在底部或抽屉中：

- **点名台**：填写当前记录并查看记录表。没有当前会话时，此页提示先新建会话或加入协作，不能在此注册。
- **会话**：新建、继续和结束会话。登录后在此进入好友与协作。
- **数据**：导出当前会话、管理词库、备份本机数据库。
- **设置**：外观、工作台、主控屏、AI、服务器与账户、应用。注册和登录位于「服务器与账户」。

> 未登录时，「会话」页的「同步与协作（可选）」为折叠状态。副标题为「需要多设备同步或与搭档共同记录时，再连接服务器。」展开后提供「设置可选服务器」。登录后该区域展开，并显示「好友与邀请」和「加入协作」。

## 按任务查找

| 目的 | 页面 | 区别 |
| --- | --- | --- |
| 创建账号 | 注册账号 | 空库的第一位管理员不经注册，见「第一个管理员」 |
| 使用已有账号 | 登录 | 扫描二维码不会登录。二维码不含密码 |
| 建立好友关系 | 加好友 | 好友关系不开放历史记录 |
| 两人记录同一会话 | 邀请别人一起记 | 账号共享和 Live Share 链接都不是加入该会话 |
| 凭邀请码加入 | 用邀请码加入 | 邀请码是旧入口，不是公开页链接 |
| 申请加入好友开放的会话 | 申请加入一场 | 仅看到标题表示尚未加入 |
| 仅在本机记录 | 自己记一场 | 结束记录不会上传，也不会公开 |

服务器是另一套程序。仅在本机记录时不必安装。需要注册、好友、共同记录或公开页时，从左侧「部署」选择一种安装方式，完成后创建第一位管理员，再注册普通账号。

## 注册账号

注册创建的是这台服务器上的账号。在客户端注册与在服务器网页注册，账号相同。用户名用于他人搜索，可使用呼号。

用户名 3 到 64 个字符，只能有字母、数字、点、下划线和连字符，不能有空格，不能以 `deleted-` 开头。用户名不区分大小写，显示时保留注册时的写法。密码至少 8 位。网页注册还需填写「确认密码」。

### 客户端

「注册」不在「会话」的主按钮上，也不在「点名台」。

1. 打开「设置」，选择「服务器与账户」。
2. 或打开「会话」。未登录时，「同步与协作（可选）」为折叠状态。展开后的说明以「新建会话即可开始记录，无需服务器或账号。」开头。选择「设置可选服务器」，打开的仍是「服务器与账户」。

### 连接服务器

1. 在「服务器地址」填写服务器根地址，例如 `https://log.example.com`。不要填写某个接口路径。
2. 可以粘贴完整链接。软件识别 `/connect`、`/client/` 和成员门户链接，并提取服务器地址。这些链接不含账号和密码。
3. 手机、macOS 和网页可扫描服务器 `/connect` 页的二维码。Linux 和 Windows 无摄像头入口，改为从图片识别。识别到地址后先确认。取消则不改变地址、当前服务器和登录状态。确认后只检测服务器，不登录，也不向新服务器提交账号。若当前已登录另一台服务器，确认框会写明将切换到的地址。
4. 点击「确认地址并连接」。进行中时按钮显示进度指示。成功后状态为「已连接」。

### 注册

1. 地址显示已连接之后，点「注册」。
2. 对话框里填「用户名」和「密码」。用户名按上面的规则，建议用呼号。
3. 成功时提示「注册并登录成功」。该提示表示注册与登录均已完成。

> 返回「会话」后，「同步与协作（可选）」展开。说明为「好友与协作使用当前服务器，本地记录仍可独立使用。」此时显示「好友与邀请」。若服务器仍提供旧的共享，还会显示「共享会话」或「旧版共享」，以及「加入协作」。

### 在服务器网页上

1. 浏览器打开 `https://log.example.com/register`。页标题是「创建账户」，字段是「用户名」「密码」「确认密码」。
2. 页面说明为「用户名不区分大小写，显示时会保留你设置的写法。」两次密码不一致时，提示「两次输入的密码不一致」。
3. 创建成功后打开 `/login`，标题为「登录 Callsign Roll Log」。已安装网页客户端时，`/client/` 为同一套记录软件，首次打开会把当前网站作为服务器地址。

### 无法完成

- 看不到「注册」：「注册」不在「会话」或「点名台」。地址尚未显示「已连接」时，先点击「确认地址并连接」。
- `/register` 无法打开或提交被拒绝：管理员已关闭「允许公开注册」。已有账号仍可登录。请管理员在管理后台的服务器设置中重新打开，或由管理员创建账号。新安装的服务器默认允许公开注册。
- 空库的第一位管理员不能通过注册产生。先完成[第一个管理员](#第一个管理员)，使用 `/bootstrap` 和引导密钥。完成后，普通成员按本页注册。
- 提示认证失败：检查用户名是否含空格或中文标点，或短于 3 个字符；密码是否短于 8 位。
- 搜索不到对方：对方未在这台服务器注册，或搜索的不是注册时的用户名。

## 登录

使用已注册的用户名和密码。仅保存服务器地址或仅扫描二维码不会登录。

### 在客户端里

1. 打开「设置 → 服务器与账户」，或在「会话」中展开「同步与协作（可选）」后选择「设置可选服务器」。地址规则见[注册账号](#注册账号)。
2. 「服务器地址」填写服务器根地址，或粘贴 `/connect`、`/client/`、门户链接。扫码确认规则与「注册账号」相同：取消不改变现有地址和登录状态；确认后只检测服务器，不登录。
3. 点击「确认地址并连接」，直到状态为「已连接」。
4. 点击「登录」，填写「用户名」和「密码」。
5. 成功时提示「已登录服务器」。失败时提示「登录失败」，并附带服务器返回的原因。

使用管理员发放的临时密码时，登录后必须先修改密码。客户端显示不可通过点击外部关闭的对话框。网页标题为「必须修改密码」，说明为「你使用了临时密码。设置新密码后才能进入门户。」新密码至少 8 位。完成前不能使用好友和协作。

> 登录后返回「会话」。「同步与协作（可选）」展开为卡片。服务器支持好友时，卡片包含「好友与邀请」和「加入协作」。未登录时不显示这两个按钮。

### 在网页上

1. 打开 `https://log.example.com/login`。
2. 填写用户名和密码。页底「还没有账户？」进入 `/register`。
3. 登录后进入 `/app`。好友位于 `/app/friends`，与客户端使用同一套数据。管理后台为 `/admin`，普通成员无法进入。

### 无法完成

- 提示「请先在设置 → 服务器与账户中检测服务器并登录」：已填写地址，但未登录或登录未成功。
- 公网和真实账号使用 HTTPS，不要使用明文 `http://`。Android 可连接受信任的局域网 `http://` 地址。
- 扫描到另一台服务器时，取消确认将保持原服务器和登录状态。确认后切换服务器，须使用该服务器的账号重新登录。
- 退出登录位于「服务器与账户」。退出不删除本机已有记录。

## 加好友

双方均须已[登录](#登录)同一台服务器。好友关系不开放历史记录、个人云或任一会话的记录。

### 入口

在「会话」中，登录后的「同步与协作（可选）」卡片上点击「好友与邀请」。页面标题为「好友与邀请」。说明为「添加搭档为好友，再邀请他们一起点名。好友关系不会自动开放个人记录。」

这一页有三个标签：

- **好友**：已建立的好友，以及「添加好友」。
- **消息**：收到的请求，以及尚未处理的已发请求。有待处理项时，标签显示数量。
- **会话**：邀请共同记录或申请加入。添加好友不使用此标签。

网页上登录后打开 `/app/friends`，处理的是同一批好友、邀请和申请。

### 发出申请

1. 在「好友」中点击「添加好友」。
2. 搜索框提示为「输入用户名或注册呼号」。至少输入 2 个字符。说明为「仅搜索当前服务器上的用户，不会搜索或公开个人记录。」
3. 点击「搜索」。无结果时显示「没有找到匹配的用户，请确认对方在同一服务器注册。」结果过多时提示「结果较多，请输入更完整的用户名。」
4. 选中对方，点击「发送申请」。发送后状态为「等待对方处理」。

### 对方接受

1. 对方打开「好友与邀请 → 消息」。
2. 在「收到的」中找到「好友申请」，点击「接受」或「拒绝」。
3. 取消自己发出且未处理的请求：在「我发出的」中取消。

> 双方「好友」列表中都能看到对方后，好友关系才建立。仅发送、对方尚未接受时，列表中没有该好友，「邀请参与」也不能选择该用户。

### 无法完成

- 会话页没有「好友与邀请」：尚未登录，或服务器不支持好友。不支持时页面显示「此服务器尚不支持好友功能，请更新服务器。」搜索提示「此服务器尚不支持用户搜索」时，同样需要先升级服务端。
- 未登录时显示「连接服务器并登录后，即可添加好友。」
- 「没有找到这个用户名」：对方未在这台服务器注册，或用户名与注册时不一致。
- 「不能添加自己」：搜索到的是当前用户名。
- 「目前无法向这个用户发送请求」：任一方已屏蔽另一方。
- 显示「对方已申请加你为好友」：在「消息 → 收到的」中接受，不要再次发送。
- 搜索太频繁会提示稍后再试。搜索失败则检查连接后点刷新。

### 删除与屏蔽

可对好友执行「删除好友」或「屏蔽」。删除会取消双方尚未处理的邀请和申请。说明为：「已加入的会话成员由会话负责人单独管理。」删除好友不移除已在会话中的成员，也不撤销已发出的账号共享。屏蔽后，新的好友申请和邀请无法发送。

## 邀请别人一起记

用于两人记录同一会话。操作者须为该会话的负责人，对方须已是[好友](#加好友)，且登录同一台服务器。

### 尚未开启协作的会话

仅保存在本机的会话不能被对方加入。须先开启协作。

1. 在「会话」中打开要共同记录的会话，确认状态为「进行中」。
2. 打开「好友与邀请 → 会话」。当前会话尚未开启协作时，此处有「开启当前会话协作」。会话页上也可能有「邀请搭档一起记录」，作用相同。
3. 确认框的标题是「上传此会话并开启协作」。正文是：这会把**当前这场和其中已经有的记录**上传到下面这台服务器，并开始协作同步。只上传这一场，不改其他场的同步。会话仍为私有。选定好友后才会发出邀请。**此操作不会发布公开页面。**
4. 确认后上传。取消则不上传，也不发送邀请。

### 发送邀请

1. 仍在「好友与邀请 → 会话」，找到该会话，点击「邀请参与」。会话页上负责人也能看到同一个「邀请参与」。
2. 对话框标题是「邀请参与」。先在「选择好友」中选择用户。没有好友时，对话框中的按钮为「添加好友」，须先完成「加好友」。
3. 权限二选一。「共同记录」可以改记录。「只能查看」不能改。说明是：「对方接受后才能查看此会话的记录，不会开放你的其他会话。」
4. 再次点击「邀请参与」。状态变为「等待对方处理」。

### 对方接受

1. 对方打开「好友与邀请 → 消息 → 收到的」。
2. 这条类型是「会话邀请」，后面带这场的名字，以及「共同记录」或「只能查看」。
3. 点击「接受」后下载并打开该会话。点击「拒绝」后，邀请方不再处于等待状态。

> 完成后，双方打开同一会话，会话标识相同。「共同记录」可以增删改自己有权限的记录；「只能查看」打开的是「查看记录」，不是「继续记录」。断线后，修改按原操作补齐，不会无故变成两条。切换页面、切换会话或暂时断网不等于退出该会话。

### 其他入口

- **跨账号共享 / 旧版共享**：将当前账号中已有的会话授权给另一个账号查看或修改。对方不必是好友，也不会因此加入该会话的实时协作。见[把已有会话给另一个账号](#把已有会话给另一个账号)。
- **Live Share**：面向观众的只读链接。持有链接的人不是成员。见[发公开页](#发公开页)。
- **邀请码**：旧入口，仍然可用。见[用邀请码加入](#用邀请码加入)。

### 无法完成

- 没有「开启当前会话协作」或「邀请参与」：尚未登录、服务器不支持好友、该会话已结束，或当前账号不是负责人。
- 「请先添加对方为好友」：已填写用户名，但双方还不是好友。
- 「对方已经加入这个会话」：不必再次邀请。在「参与者与邀请」或「协作与成员」中查看其权限。
- 结束共同记录时，不要使用会话页的本地「结束记录」。界面会要求在「协作与成员」中选择「结束共同记录」。结束后所有成员不能再修改，已有记录和成员关系保留。参与者退出时点击「离开协作」：本机已有记录变为只读，其他成员继续。之后需重新邀请或再次申请。离开页面不等于离开协作。

## 用邀请码加入

这是旧入口，目前仍可用。两个人已经是好友时，优先用[邀请别人一起记](#邀请别人一起记)。邀请码不是 Live Share 链接，也不是账号密码。

### 使用邀请码

须先[登录](#登录)发放邀请码的那一台服务器。未登录时，「会话」页不显示「加入协作」。

1. 登录后回到「会话」，在「同步与协作（可选）」里点「加入协作」。
2. 对话框标题是「加入协作」。说明是「输入成员邀请码。成功后会以远端相同的 Session ID 安装完整本地副本。」
3. 「邀请码」一栏的例子是 `ABCDE-12345`。大小写会按呼号那样处理。为空时「加入」不可用。
4. 点「加入」。成功时提示「已加入协作会话」，并打开该会话。本机安装的是与服务器相同的那一场，不是新建的另一场。

### 生成邀请码

操作者须为该会话的负责人。会话须已是协作会话，且服务器仍提供邀请码。

1. 在「会话」中打开该会话。已是协作会话时，按钮中有「协作与成员」。点击进入。
2. 页面包含成员、邀请码、公开页等部分。点击「邀请码（兼容旧版）」。
3. 该部分标题为「成员邀请」。先选「编辑者」或「只读成员」，再点「生成」。
4. 成功提示「邀请码已生成」。邀请码只在本次创建响应中显示。须立即复制。关闭或刷新后无法再次查看，只能重新生成。尚未使用的旧码可在列表中撤销。

> 对方用这个码加入之后，权限为生成时选择的那一档。「编辑者」对应能改记录，「只读成员」只能看。和好友邀请里的「共同记录」「只能查看」是同一类区别，只是入口不同。

### 无法完成

- 找不到「加入协作」：尚未登录。登录后它位于「同步与协作（可选）」卡片，不在「点名台」。
- 找不到「协作与成员」：该会话仍只在本机，尚未开启协作。先按邀请页上传该会话，或当前没有会话。
- 没有「邀请码（兼容旧版）」这一段：这台服务器不再提供旧邀请码。改用好友邀请。
- 将 Live Share 链接或网页地址填入邀请码：无法匹配。邀请码是生成时单独显示的那一串字符。
- 对方提示邀请码无效：该码可能已撤销或不再被服务器接受。重新生成后发送新的邀请码。

## 申请加入一场

须由负责人开放该会话。申请者须已与负责人互为[好友](#加好友)，并登录同一台服务器。默认会话为私有，好友不可见。

### 开放加入

1. 该会话须已是协作会话。仍只在本机时，先按[邀请别人一起记](#邀请别人一起记)里的「开启当前会话协作」上传。该步骤不会自动向好友公开。
2. 打开「好友与邀请 → 会话」，找到自己是负责人的那场。
3. 「加入方式」三选一，只影响这一场：

| 选项 | 好友侧结果 |
| --- | --- |
| 仅邀请 | 该会话不出现在好友的列表中。只能由负责人点击「邀请参与」，或使用邀请码。界面上也会写成「仅邀请可加入」。 |
| 好友申请，审批后加入 | 好友能看到标题，按钮是「申请加入」。负责人在「消息」中接受后，对方才能查看记录。仅看到标题表示尚未加入。 |
| 好友直接加入 | 同一台服务器上的好友无需审批即可加入，并能看到该会话已有和此后新增的全部记录。打开前会要求确认。只影响这一场，其他会话仍然私有。该权限只对之后直接加入的人生效，已在会话中的成员不变。已被移出的人须重新邀请或再次审批。 |

### 提交申请

1. 打开「好友与邀请 → 会话」。没有开放的会话时，显示「暂无好友开放的会话。你也可以把当前会话用于协作。」
2. 在对方的该会话上，需要审批时点击「申请加入」。对话框显示该会话名称。选择「共同记录」或「只能查看」后，再次点击「申请加入」。
3. 对方开启直接加入时，按钮为「直接加入」，并标明新成员是「共同记录」还是「只能查看」。
4. 需要审批时，负责人到「好友与邀请 → 消息 → 收到的」，这条类型是「加入申请」，点「接受」或「拒绝」。自己发出的请求在「我发出的」。

> 接受后，申请者会下载该会话并可以打开。在此之前，申请者只能在列表中看到标题。负责人也可以不等待申请，直接使用「邀请参与」邀请指定好友。

### 无法完成

- 好友的「会话」中没有该会话：加入方式仍为「仅邀请」，或对方登录的不是这台服务器，或双方还不是好友。
- 「申请加入」不可用：该申请已处于「等待对方处理」。等待负责人处理，或在被拒绝后重新申请。
- 负责人已改为必须审批，而页面仍是旧状态：刷新。界面会提示负责人已改为申请加入，请刷新后提交申请。
- 已被移出该会话时，不能通过原来的直接加入再次进入。提示为「你已被移出此会话，请联系负责人重新邀请。」

## 自己记一场

不需要服务器，也不需要账号。记录留在这台设备上。结束记录不会上传，也不会变成公开页。

### 新建

1. 打开本机客户端，或已部署的网页客户端。尚未安装时见[安装客户端](#安装客户端)。
2. 点「会话」。这一页的主按钮是「新建会话」。没有服务器时，这里不会出现「加入协作」或公开分享。
3. 对话框标题是「新建点名会话」。名称预填为当前日期和时间，可以修改。取消则不创建。确认后，该会话成为当前会话。

### 点名台

点「点名台」。没有当前会话时，这里不是一张能填的空表，而是提示先新建会话或加入协作。此页不能注册。

1. 一条记录上有：主控呼号、来台呼号、设备、天线、功率、QTH、高度、时间、信号报告、备注。
2. 呼号会转为大写。主控呼号填写后会保留，连续记录下一条时不必再填。
3. 设备、天线、呼号和 QTH 会按词库联想。新输入的内容会进入这四类词库。功率和高度不进这四类词库。
4. 来台呼号为空时不能保存，提示「请输入点名呼号」。填写后点击「保存记录」。成功时提示「记录已添加」。
5. 刚保存的上一条可以撤销。表中已有记录可以再次打开并编辑，或删除。

> 在「设置 → 工作台」打开「呼号历史一键复用」后，呼号栏可按本机以往记录填回设备、天线、QTH、功率和高度。使用的是本机历史，不是他人的词库。

### 结束与继续

1. 返回「会话」，在该会话上点击「结束记录」。确认框标题为「结束记录」。正文为：结束这场的记录吗？已有记录会保留，可随时查看或恢复。此操作不会删除数据。
2. 确认后提示「记录已结束，已有记录已保留」。切换页面、关闭软件或暂时离开不会结束记录。客户端不会因闲置自动结束记录。
3. 历史可按「全部」「我的记录」「共同记录」「已结束」筛选。没有任何协作副本时，不显示「共同记录」。历史区说明为：「已结束」只按会话状态筛选，不代表公开归档。
4. 仍在进行中的会话，点击「继续记录」。已结束的本地会话，点击「重新激活」。确认框为：恢复这场并切换过去继续记录吗？其他会话不受影响。协作会话不能在此作为本地会话重新打开，须由发起人在「协作与成员」中恢复。

### 删除本机会话

「永久删除本机数据」要求输入完整会话名。删除的是本机上的该会话及其记录。确认文案说明：不会删除或关闭服务器上的共享会话。停止记录使用「结束记录」，不使用删除。

### 无法完成

- 点名台没有表单：没有当前会话。返回「会话」，点击「新建会话」。
- 「结束记录」被拒绝并提示这是共同记录：该会话已在协作中。在「协作与成员」中选择「结束共同记录」，或点击「离开协作」。不能按仅本机会话结束。

## 导出、词库和备份

这些都在「数据」里。上面有四个标签：「记录与导出」「查询词库」「本地数据库」「同步冲突」。

### 当前会话

位于「记录与导出」。此页管理的是**当前会话**的点名记录，不是整台设备的库。

- 「导出 JSON」：标准 JSON，带全部字段，适合备份和迁到别的程序。
- 「导出 Excel」：`.xlsx`，带分组的主控行、颜色和页脚，适合查看、转发和打印。账号如果同步了 Excel 样式，导出会按那套抬头和文件名来。要改抬头、颜色或文件名模板，点「编辑设置」。
- 「导出 ADIF」：按每个主控呼号各出一份 `.adi`，可以再导入 LoTW 或 QRZ。多个主控时打成一个 zip。本机记录里没有模式和频段，导出前对话框标题是「导出 ADIF」，须选择本次使用的「模式」和「频段」。
- 「导入 JSON」「导入 Excel」：把文件里的点名记录导入**当前这场**。先确认「会话」中打开的是准备导入的目标会话。

「导出路径」留空时，用系统下载目录。该栏说明为「留空时使用系统下载目录」。

### 词库

「查询词库」管的是点名时用来联想的设备、天线、呼号和 QTH。可以搜索，也可以把词库导出成 JSON，或从 JSON 导入。

软件自带的条目与用户添加的条目不同。个人云只上传用户添加的词条，以及删除内置词条的记录，不会再次上传整份内置词库。

可选的「文字助手」在「设置 → AI 辅助」，默认关闭。它只根据本机历史提出「词库里缺了什么、要不要改名或合并」。确认之前不修改词库，也不修改已有记录。

### 整库备份

更换设备，或需要防备本机故障时，使用「本地数据库」，不要只使用上面的单场导出。

1. 「导出本机数据库」。说明是：备份会话、记录、词库，以及本机协作副本和待同步状态。成功提示「本机数据库备份已导出」。
2. 在另一台，或在这台恢复时，点「导入本机数据库」。先选 JSON 备份。预览标题是「确认导入备份」，里面有备份格式版本、导出时间、会话数、点名记录数、词库条目数、协作副本数、待同步或待复核的数量。
3. 核对后再点击「覆盖并导入」。警告写明：这会完整覆盖当前这台设备的库，包括还没同步的更改。服务器上的会话、安全存储里的登录凭据、应用设置都不受影响。内置词库会按当前版本补齐。此操作不可撤销。备份里如果有协作副本，服务器地址和登录账户对得上时，导入后可能继续同步。
4. 成功提示「本机数据库已导入，界面数据已刷新」，并显示会话数和记录数。可在「会话」中查看历史。

> 「清空本机数据」会清掉本机的会话、点名记录、协作副本、待同步队列和自定义词条，并把内置词库恢复成默认。不会删除或关闭服务器上的会话，也不会退出登录或重置外观。确认时必须输入「清空全部数据」，按钮才是「永久清空本机数据」。

### 同步冲突

「同步冲突」只在登录并打开了个人云、而且两边改了同一处时才要进。没有冲突时，这一页会说当前没有需要选择的冲突，同步入口在「本地数据库」。怎么选，见[换一台设备](#换一台设备)。

### 无法完成

- 导出为空：当前会话中还没有记录，或「会话」中打开的不是目标会话。
- 导入整库时提示正在发布、加入或处理别的协作：等待该操作完成后再导入。不要在协作操作进行中覆盖本机库。
- 选中的文件提示不是有效的数据库备份：该文件是单场记录 JSON，不是「导出本机数据库」生成的整库文件。单场文件使用「记录与导出」中的导入。

## 换一台设备

更换电脑或手机后继续记录自己的会话，使用个人云。两台设备登录**同一个账号**，且服务器须提供个人云。这不是将会话交给他人，也不是协作。

### 入口

「数据 → 本地数据库」，区域名称为「个人云同步」。说明为：个人会话、点名记录和词库改动会在已登录设备间自动双向同步；协作会话仍走自己的实时协作。

未登录时，此处显示「登录服务器后自动同步个人记录和词库改动」。登录后会自动同步。进行中显示「正在同步个人记录和词库改动…」。完成后显示「个人记录和词库改动均已同步」。也可点击「同步个人快照」立即同步一次。

这一块会列出本机有多少场、多少条，以及账户云快照有多少场、多少条。词库另计已修改的项，不是整份内置词库。

### 配对

1. 第一台按[登录](#登录)登进这台服务器，确认上面的状态变成已同步。本机上的个人会话才会进入云快照。
2. 第二台安装客户端，填**同一台**服务器，用同一个用户名和密码登录。
3. 打开「数据 → 本地数据库」。两边改的不是同一处时，会自动合并。首次配对或需要确认时，状态为「首次配对或真实编辑冲突需要确认；互不冲突的改动已安全合并。」核对两边数量后，点击「确认安全合并」。

> 从云端换下来的是个人记录和词库改动。不会改这台设备的设置，也不会改协作会话。个人记录不会写进协作会话，也不会出现在服务器的协作会话列表里。

### 字段冲突

只有同一个字段两边都改过，才需要选择。打开「数据 → 同步冲突」。页标题是「个人云同步冲突」。说明是：逐项比较本机、云端和共同基线。每一项都须明确选择后才会合并。协作会话的冲突不在此页，仍在会话中处理。

- 可以「全部选本机」或「全部选云端」，也可以逐项「保留本机」「保留云端」。
- 进度是「已选择多少项」。没有全部选完时，「应用选择」不会做完。
- 完成后提示「冲突选择已应用并完成同步」。

没有字段冲突、但还要确认第一次合并时，此页要求返回「本地数据库」核对数量，再点击「确认安全合并」。

### 整份替换

都在「本地数据库」的个人云一块里。两项操作都要求输入完整确认句。

- 「以本机替换云快照」：用这台设备上的个人记录，整份换掉账户云里的个人记录，其他已登录设备随后也会变成这份。确认句是「用本机记录替换账户云快照」。不会写入或修改协作会话。
- 「从云快照恢复本机」：用账户云里的个人记录换掉这台设备上的个人记录。词库、设置和协作会话不受影响。确认句是「用账户云快照替换本机记录」。

整库导入或清空之后，自动覆盖会先停住，等待确认新的同步基线。尚未核对两边数量时，不要点击「以本机替换云快照」。

### 无法完成

- 「当前服务器版本不支持账户个人云快照，请先升级服务器」：这台服务器太旧。升级之前，换设备只能走[导出、词库和备份](#导出、词库和备份)里的整库文件。
- 第二台已登录但会话为空：账号不同、服务器不同，或第一台尚未同步完成。返回第一台，确认状态是否为「均已同步」。
- 将会话交给另一账号不使用个人云。共同记录见[邀请别人一起记](#邀请别人一起记)。已有会话授权见[把已有会话给另一个账号](#把已有会话给另一个账号)。

## 把已有会话给另一个账号

将当前账号中已有的会话授权给另一个账号查看；在允许修改时，对方可以修改记录。对方须在同一台服务器上有账号，不必先成为好友。对方不会因此加入该会话的实时协作，当前正在记录的会话也不会被切换。

### 入口

先[登录](#登录)。回到「会话」，在展开的「同步与协作（可选）」里。服务器还提供这项旧能力时，才会有下面三个名字之一的按钮：

- 服务器能一次共享多场：按钮是「共享会话」。
- 服务器有好友、但这边仍是旧入口：按钮是「旧版共享」。
- 服务器没有好友功能、只剩旧的账号共享：按钮是「跨账号共享」。

没有该按钮，表示这台服务器不再提供旧共享入口。新的共同记录从「好友与邀请」进入，见[邀请别人一起记](#邀请别人一起记)。

### 发送

1. 点上面那个按钮。能多选时，对话框标题是「共享会话」。
2. 范围二选一。「持续共享全部」包含现在和以后新建的本人会话。新的本地会话要先完成个人云同步，对方才看得到。「多选会话」只共享勾上的场，以后新建的不会自动算进去，也不会把他人共享来的会话再次转出。
3. 权限。「仅查看」只能看。「允许新增、修改记录」可以改。要允许删记录，必须另外打开，而且必须同时允许修改。删除整个会话、结束会话、再转授给别人，始终只有所有者能做。已经结束的会话只能查看。
4. 接收人：选择好友，或输入同一台服务器上的用户名。没选人、又没勾场，也没选持续共享全部时，发不出去。
5. 点「发送共享邀请」。

### 对方接受

1. 对方在同一台服务器登录。收到的在「收到的共享邀请」。没有待处理时，这里是「暂无待处理的共享邀请」。
2. 接受之后，提示是：已接受共享邀请，可以在「历史会话 → 共享」中查看。当前记录会话不会切换。
3. 对方到「会话」的历史里打开「共享」，再点击「浏览共享会话」查看被授权的会话。

> 完成后，对方看到的是被授权的会话，而不是一场实时共同记录。两人同时记录同一会话时，使用[邀请别人一起记](#邀请别人一起记)。

### 词库开关

「共享词库」是这项授权上的一个开关，新开的授权默认打开。更早发出、当时还没有这个开关的授权保持关闭。服务器太旧、没有这项能力时，客户端不显示这个开关。

打开之后，对方只能在这些共享会话中使用授权方的设备、天线、QTH 做联想。在被允许修改记录时，还可以按呼号填回设备、天线、QTH、功率和高度。对方不能修改授权方的词库，内容也不会写入对方自己的词库或数据库。关闭开关或撤销授权后，对方不能再使用。

### 撤销

「已发出的共享」里点「撤销共享」。撤销后，对方不能再靠这项授权查看或操作。已经另外加入某场协作的人，不因这次撤销被移出那场协作。

### 无法完成

- 找不到「共享会话」「旧版共享」或「跨账号共享」：还没登录，或这台服务器已经不再提供这个入口。
- 接受后当前会话没有切换：接受共享邀请不会切换正在记录的会话。共享来的会话在历史的「共享」中查看。
- 对方看不到新建会话：范围为「多选会话」时，新建会话不会自动包含。改为「持续共享全部」，或另行勾选该会话。持续共享的新建会话须先完成云同步。

## 发公开页

公开页面须由该会话的所有者发布。在「会话」中点击「结束记录」不会发布公开页。历史中的「已结束」只表示本机状态。

### Live Share

供未安装软件的人查看当前进度。对方不必登录，也不是该会话的成员。

1. 会话须已是协作会话，且当前账号为所有者。会话仍只在本机时，先按[邀请别人一起记](#邀请别人一起记)中的步骤上传。该确认框写明：不会发布公开页面。
2. 在「会话」里打开这场，点「协作与成员」。
3. 找到「Live Share · 公开只读页面」。说明是：为主控、远程书记员或观众生成只读网页，无需登录即可查看当前点名进度。链接密钥只在创建时显示。
4. 点「创建公开链接」。对话框标题是「设置 Live Share 有效期」。可选 1 小时、6 小时、12 小时、1 天、3 天、7 天、30 天，或自行填写小时数。范围是 1 到 720 小时，即最短 1 小时、最长 30 天。不修改时使用默认时长。
5. 创建成功的标题是「公开只读页面已创建」。正文要求立即保存该链接。刷新或重新登录后，无法再次取得链接中的密钥。

> 密钥在链接的 `#` 后面。转发时不要改成 `?token=` 查询参数，也不要删除 `#` 后面的内容。对方打开的是只读页，不能在该页记录。

已有有效链接但当时未保存密钥：列表说明密钥只在创建时返回。撤销旧链接后，再次点击「创建公开链接」。过期或撤销之后，状态是「已撤销或已过期」。

### 公开归档

这是已结束记录的静态页面，不跟着现场改。和 Live Share 不是同一个链接，也不在「协作与成员」那一块里。

1. 用浏览器登录这台服务器的成员门户 `/app`。左侧或导航里有「公开归档」。
2. 页标题是「公开归档列表」，说明是管理已关闭会话的静态公开归档。点「创建归档」，填标题。
3. 「添加已关闭会话」。至少加入一场已结束的会话后才能发布。未添加会话就发布时，会提示先添加。
4. 点「发布」。需要转发时点击「复制公开链接」或「打开公开页面」。停止公开时点击「取消发布」。

成员可以管归档里的内容。成员名单和来源账户，只有所有者或管理员能改。根路径别名在管理后台的「公开归档别名」里设置。用了别名时，反向代理也要把那个路径原样转到服务器，见[前面加 HTTPS](#前面加 HTTPS)。

### 主控屏

「设置 → 主控屏」打开「主控显示」。它把当前这一条显示给操作员或现场屏幕。桌面端可从会话页打开独立窗口。未安装软件的观众使用上面的 Live Share，不使用主控屏。

### 无法完成

- 「协作与成员」里没有 Live Share，或提示当前服务器未提供：这台服务器没开公开分享，或太旧。先升级服务器。
- 提示 Live Share 由当前协作会话的 Owner 管理：当前账号不是所有者。由所有者创建，或先将该会话开启为协作会话。
- 链接可以打开，但页面持续重连：通常是前面的 HTTPS 代理未正确转发 `/ws`。见[前面加 HTTPS](#前面加 HTTPS)。
- 公开归档无法加入该会话：该会话尚未结束。Live Share 用于进行中的会话，归档只接受已关闭的会话。

## 数据在这台设备的哪里

点名记录在这台设备自己的库里。服务器上另有一份，只包含已上传的协作、个人云和账号数据。两边不是同一个文件。

### 桌面和手机

数据库文件名是 `openlogtool_rust.db`，在系统给这个应用的支持目录里。软件运行时不要直接修改、复制或删除该文件。更换设备时，在「数据 → 本地数据库」导出，再在另一台导入，见[导出、词库和备份](#导出、词库和备份)。

诊断日志是同一目录里的 `app.log`。软件里从「设置 → 应用」打开「日志」，说明是「查看持久化诊断日志、错误与应用内消息」。正常记录时不必查看。

崩溃文件不在 `app.log` 里。原生崩溃不经过界面上的这条日志：

- Windows：`%LOCALAPPDATA%\Callsign Roll Log\CrashDumps\` 下的 `.dmp`。
- Linux：`$XDG_DATA_HOME/openlogtool/crashes/`，没有单独设置时回退到 `~/.local/share/openlogtool/crashes/`。
- macOS：系统的 `~/Library/Logs/DiagnosticReports/` 里对应的 `.ips`。应用自己不另写一份。

### 网页

网页版用同一个文件名，但由浏览器按网站来源保存。协议、域名、端口任一不同，即为另一份数据。`https://log.example.com` 和 `http://127.0.0.1:5973` 里的记录互不相通。

清除这个网站的站点数据、缓存或浏览器配置，本地记录会一并删除。除了浏览器承认的本机地址，网页版需要 HTTPS。

### 服务器上的库

服务器的数据库默认是仓库目录里的 `data/openlogtool.db`。那是账号、协作和个人云的库，不是本机的 `openlogtool_rust.db`。备份服务器时要带走 `data/` 和 `.env`，见[更新已有服务器](#更新已有服务器)。

## 安装客户端

仅在本机记录时，安装客户端即可。安装包在[下载](https://crl.mazha0309.com/#download)。服务器是另一套程序，需要注册和共同记录时才安装，见[开始之前](#开始之前)。

### Windows

便携包要整包解压，再运行里面的程序。不要只复制其中的 exe。正式便携包已包含所需运行库，不要求系统另行安装 VC++ 运行库。安装版会带上同一套运行库。

部分 Windows 环境在读屏或无障碍开启时会发生原生崩溃，各版本均可能遇到，软件内没有对应开关。崩溃目录见「数据在这台设备的哪里」。若程序打开后立即退出，先查看该目录。此问题与记录步骤无关。

### macOS

首次打开未签名的应用时，系统提示开发者未验证。已发布的 3.0.3-R 在部分 Mac 上会在启动时被系统终止。这是已知问题，需等待包含修复的新安装包。设置中没有可绕过该问题的开关。

### Linux

桌面端运行需要 `libsecret-1-0`，以及一个能用的密钥环（Secret Service）。没有密钥环时，登录状态和密钥无法保存。Debian、Ubuntu 一类系统可以安装：

```
sudo apt install libsecret-1-0 gnome-keyring
```

### Android

用发布的安装包安装。Android 允许连接本机所在局域网内的明文 `http://` 服务器。公网和真实账号仍然用 HTTPS，不要用明文 HTTP 去登录一台公网服务器。

### 网页客户端

服务器如果已经装了网页客户端，浏览器打开 `https://log.example.com/client/`。首次打开会把当前网站作为服务器地址。该浏览器中的记录按网站来源分开保存，域名不同即为另一份，见[数据在这台设备的哪里](#数据在这台设备的哪里)。

只部署了网页客户端、没有服务器时，它只能完成本地记录。注册和共同记录仍需要另行部署的服务器。

## 开始之前

仅在本机记录时不必部署服务器。按[安装客户端](#安装客户端)下载。

需要注册、好友、共同记录、个人云或公开页时，部署这套服务器。网页客户端可以与服务器放在同一网站，也可以单独部署，见[网页客户端](#网页客户端)。

四种安装方式选择一种，直到本机可以打开页面。密钥只生成一次。升级时不要重新生成，否则已经发出的登录、邀请码和 Live Share 链接会失效。

- 新机器、希望少执行命令：[Docker Compose 一键](#Docker Compose 一键)。
- 仓库已经克隆在这台机器上，用 Docker：[已经克隆好的 Docker](#已经克隆好的 Docker)。
- 不使用 Docker，由脚本拉取代码并保持运行：[原生 Node.js 一键](#原生 Node.js 一键)。
- 在本机前台运行或修改代码：[直接运行](#直接运行)。

### 服务器要先有四把密钥

一键脚本会生成并写入 `.env`。自行使用 Docker 或 `npm start` 时，在服务器仓库目录先做这一步：

```
cp .env.example .env
openssl rand -hex 32
openssl rand -hex 24
openssl rand -hex 32
openssl rand -hex 32
```

四个输出各使用一次，填入 `.env`。四项不能使用同一个值：

```
JWT_SECRET=<至少 32 字节>
ADMIN_BOOTSTRAP_TOKEN=<至少 24 字节>
INVITE_HMAC_KEY=<至少 32 字节>
PUBLIC_SHARE_HMAC_KEY=<至少 32 字节>
```

- `JWT_SECRET`：登录之后的令牌。生产环境不接受示例里的默认值。
- `ADMIN_BOOTSTRAP_TOKEN`：空库创建第一个管理员时用的引导密钥。空库第一次启动必须有它。创建管理员之后，不要把它当作日常登录密码。
- `INVITE_HMAC_KEY`：旧邀请码。不能和登录密钥相同。
- `PUBLIC_SHARE_HMAC_KEY`：Live Share 和公开页。必须单独设置，不能与其他密钥相同。

`.env` 不要提交到仓库，也不要发送给他人。在线备份是整份数据库，含密码哈希，但不包含 `.env`。更换机器时，数据库和 `.env` 都要保留。

> 页面可以打开后，下一步不是开放 `/register`。空库须先完成[第一个管理员](#第一个管理员)。管理员创建后，普通成员才能注册。

## Docker Compose 一键

适合一台新的机器。脚本负责克隆、密钥、构建和启动。机器上要有 Git、Docker 和 Docker Compose v2，不必再装 Node.js。

### 执行

末尾的 `3000` 是宿主机端口。使用其他端口时，将该数字替换为实际端口。

```
curl --proto '=https' --tlsv1.2 -fsSL \
  https://raw.githubusercontent.com/Mazha0309/CallsignRollLogServer/main/deploy-docker.sh \
  | bash -s -- 3000
```

脚本从 `main` 克隆或快进，生成并保留四把密钥，构建镜像，启动后做健康检查。已有数据库会在镜像构建成功后停服，备份到 `~/OpenLogToolServer-backups/<时间>/`。不会覆盖已有代码修改，也不会更换已有密钥。

### 完成后

1. 本机浏览器打开 `http://127.0.0.1:3000`，能看到服务器页面，而不是连接被拒绝。
2. 再打开 `http://127.0.0.1:3000/api/v1/server-info`，能返回服务器信息，而不是 502 或空响应。
3. 仓库目录里已经有 `.env`。以后升级不要删它，也不要重新跑四次 `openssl` 去覆盖。

该地址仅供本机访问。向他人提供访问前，按[前面加 HTTPS](#前面加 HTTPS)放到反向代理后面，不要把明文 HTTP 的 3000 端口直接暴露到公网。

下一步做[第一个管理员](#第一个管理员)。网页客户端还没装时，`/client/` 打不开记录软件，成员门户和接口不受影响。要装的话看[网页客户端](#网页客户端)。

### 无法完成

- 提示没有 docker 或 compose：先安装 Docker Engine 和 Compose v2，再执行。不要改用旧命令名 `docker-compose`，除非该命令实际为 Compose v2。
- 仓库里有未提交的已跟踪修改，或不能快进：脚本会停。先处理这些修改。不要为了让脚本继续而丢弃改动。
- 构建时 npm 较慢：一键脚本不提供镜像源参数。仓库已克隆且需要指定镜像源时，改用[已经克隆好的 Docker](#已经克隆好的 Docker) 里的 `NPM_REGISTRY`。
- 页面无法打开：在仓库目录执行 `docker compose ps`。服务不是 Up 时，查看 `docker compose logs server`。常见是 `data` 目录容器写不进去，或端口 3000 已经被占用。

## 已经克隆好的 Docker

仓库已经在这台机器上。先按[开始之前](#开始之前)写好 `.env`，四把密钥不要用示例默认值。

### 启动

在仓库目录：

```
mkdir -p data
sudo chown -R 1000:1000 data
chmod 700 data
docker compose up -d --build
docker compose ps
```

数据库在 `./data/openlogtool.db`。容器里的进程以 UID 1000 运行，所以 `data` 目录要允许这个用户写入。权限不正确时，数据库无法创建，页面也无法启动。

默认只发布到宿主机的 `http://127.0.0.1:3000`。`docker compose ps` 里 server 应是 Up。再检查：

```
curl -fsS http://127.0.0.1:3000/api/v1/server-info
```

返回 JSON 表示进程已在监听。随后创建[第一个管理员](#第一个管理员)。

### 构建时指定镜像源

可以先指定镜像源再启动。这只影响构建时下载依赖，不修改密钥，也不修改数据库：

```
NPM_REGISTRY=https://registry.npmmirror.com docker compose build
docker compose up -d
```

### 无法完成

- `data` 仍是 root 拥有、容器无法启动：再执行一次上面的 `chown`。不要把整个仓库 `chmod 777`。
- 修改了 `.env` 但未生效：环境变量要重建容器才读到。`docker compose up -d --force-recreate server`。只改环境变量时不必重新构建镜像。
- 想让局域网直接访问这个端口：这是例外，不是默认。公网用反向代理。要改绑定地址时见[配置](#配置)里的 `BIND_ADDRESS`。

## 原生 Node.js 一键

不使用 Docker。机器上需要 Git、Node.js 24.18 或更高版本，以及 npm。Node 版本不足时，先安装再执行。脚本不会修改系统软件源。

### 执行

末尾的 `3000` 是端口。

```
curl --proto '=https' --tlsv1.2 -fsSL \
  https://raw.githubusercontent.com/Mazha0309/CallsignRollLogServer/main/deploy.sh \
  | bash -s -- 3000
```

已安装 PM2 时用 PM2 保持运行，否则使用 `nohup`，日志在仓库目录的 `server.log`。`server.log` 不要提交进仓库。

已有的 `.env` 和 `./data/openlogtool.db` 会保留。仓库里有未提交的已跟踪修改，或者不能快进时，脚本会停下来，不会覆盖已有修改，也不会重新生成密钥。

### 完成后

1. 本机打开 `http://127.0.0.1:3000`。
2. `curl -fsS http://127.0.0.1:3000/api/v1/server-info` 有返回。
3. 使用 PM2 时，`pm2 ls` 中应能看到该进程。使用 nohup 时，`server.log` 中不应持续出现启动错误。

下一步做[第一个管理员](#第一个管理员)。向他人提供访问前，按[前面加 HTTPS](#前面加 HTTPS)。

### 无法完成

- `node -v` 低于 24.18：先升级 Node，再执行。不要使用版本不足的系统 Node。
- 脚本停在 git：存在未提交修改，或本地分支不能快进到 `main`。先处理仓库，不要删除 `.env` 后重新开始。
- 端口已被占用：把命令末尾的 `3000` 换成空闲端口，并在后面的检查和反向代理里用同一个端口。

## 直接运行

用于在本机前台运行，或修改服务端代码。关闭终端或按 Ctrl+C 后进程停止。需要持续运行时，使用[Docker Compose 一键](#Docker Compose 一键)或[原生 Node.js 一键](#原生 Node.js 一键)。

### 启动

在仓库目录，先按[开始之前](#开始之前)写好 `.env`。需要 Node.js 24.18+ 和 npm 10+。

```
npm ci
(cd web && npm ci)
(cd live && npm ci)
npm start
```

`npm start` 在前台运行。本机打开 `http://127.0.0.1:3000`，并用 `curl -fsS http://127.0.0.1:3000/api/v1/server-info` 确认。空库接着做[第一个管理员](#第一个管理员)。

### 开发运行

开发时用 `npm run dev`，改完会重新加载。这不是对外提供服务的运行方式。

提交前的完整检查是 `npm run verify`。它时间很长，而且不使用仓库里的生产数据库。不要为了运行检查而指向正在提供服务的 `data/openlogtool.db`。

### 无法完成

- 启动后立即退出并报告密钥错误：`.env` 缺了四把之一，或 `JWT_SECRET` 仍是示例默认值。回到[开始之前](#开始之前)。
- `web` 或 `live` 没装依赖：把上面的两个 `npm ci` 补上。只在仓库根目录 `npm ci` 不够。
- 端口被占用：改 `.env` 里的 `PORT`，再启动。检查用的 URL 也要改成那个端口。

## 第一个管理员

空库不会把第一个通过 `/register` 注册的账号设为管理员。初始化只能成功一次。服务器页面已经能打开之后再做这一页。

### 在网页上

1. 浏览器打开 `http://127.0.0.1:3000/bootstrap`。已配置 HTTPS 时，使用该域名，路径仍为 `/bootstrap`。
2. 页标题是「初始化首位管理员」。
3. 「引导密钥」填 `.env` 里的 `ADMIN_BOOTSTRAP_TOKEN`。不是随后使用的登录密码。
4. 再设定管理员的用户名和密码。用户名规则与普通注册相同：3 到 64 个字符，字母、数字、点、下划线、连字符。密码至少 8 位。
5. 点「初始化服务器」。成功之后，这个地址不应再用来创建第二个管理员。

### 命令行

在服务器本机执行。将引导密钥和密码替换为实际值。不要把含密钥的命令发给他人：

```
curl -X POST http://127.0.0.1:3000/api/v1/auth/bootstrap \
  -H 'Content-Type: application/json' \
  -H 'X-Bootstrap-Secret: <ADMIN_BOOTSTRAP_TOKEN>' \
  -d '{"username":"admin","password":"replace-with-a-strong-password"}'
```

### 完成后

1. 打开 `/login`，用刚设定的用户名和密码登录。能够进入 `/admin`，才表示该账号是管理员。
2. 普通成员能否自行注册，由管理后台服务器设置中的「允许公开注册」控制。新安装默认允许。关闭后，`/register` 和客户端中的「注册」都会失败，已有账号仍可登录。
3. 管理员也可以打开 `/app` 记录。未加入某一会话时，看不到该会话的成员内容。管理员身份不会自动获得全部会话的成员权限。

> 引导密钥留在 `.env` 里，但日常登录用的是上面设的密码。将引导密钥填入登录框无法登录。

### 无法完成

- `/bootstrap` 拒绝，或提示已经初始化：这台库不是空的，第一个管理员已经有了。使用该管理员账号打开 `/login`。忘记密码时，不要再次执行初始化。
- 引导密钥始终失败：应填写的是 `ADMIN_BOOTSTRAP_TOKEN`，不是 `JWT_SECRET`。改过 `.env` 之后要重启进程或重建容器，新值才会被读到。
- 通过 `/register` 创建的是普通成员，不会成为管理员。若尚未创建管理员，按本页操作。

## 网页客户端

网页客户端是浏览器中的记录软件，与服务器是两个程序。放在一起时，成员打开同一网站即可记录。单独部署时，该容器不提供注册、好友和协作。

## 网页客户端和服务器放在一起

成员打开 `https://log.example.com/client/`，不必再填写另一套地址。构建机须具备客户端仓库要求的 Flutter 和 Rust Web 环境。两份仓库按下面的相对位置放置：服务器仓库为 `OpenLogToolServer`，客户端仓库位于其旁，目录名为 `openlogtool`。

```
cd ../openlogtool
bash tool/build_web.sh --base-href /client/
cd ../OpenLogToolServer
node scripts/install-web-client.mjs ../openlogtool/build/web
```

装好后重启 Node。Docker 则在服务器仓库执行：

```
docker compose up -d --force-recreate server
```

然后逐项检查：

- `/connect` 有地址和二维码。二维码里没有账号和密码。检测到网页客户端之后，这里才有进入客户端的按钮。
- `/client/` 能打开记录软件，而不是 404。
- 登录之后，`/app/friends` 是好友入口。未登录时无法打开该页，这是预期行为。

没有这份产物时，原来的接口、成员门户和管理后台不受影响。只是不提供 `/client/`。

## 只部署网页客户端

该容器不是服务器，不提供注册、好友和协作。它是浏览器中的记录软件，默认端口 5973。共同记录须另行部署服务器，并在网页客户端的「设置 → 服务器与账户」填写该服务器地址。

从源码，在客户端仓库：

```
docker compose -f docker-compose.web.yml up -d --build
```

本机打开 `http://127.0.0.1:5973`。换端口用 `OPENLOGTOOL_WEB_PORT=8080`，容器里面仍然监听 80，反向代理的目标是映射出的宿主机端口，不是容器内的 80。

从发布包（不必在部署机器上编译）：

```
tar -xzf Callsign\ Roll\ Log-*-WebClient.tar.gz
cd Callsign\ Roll\ Log-*-WebClient
docker compose up -d
```

公网使用时，用 HTTPS 反向代理转到 `127.0.0.1:5973`。网页客户端和服务器的协议、域名或端口只要有一个不同，就要在服务器上设置 `CORS_ORIGINS`，见[配置](#配置)。

> 单独部署的网页客户端可以完成本地记录，但不能注册。注册和共同记录需要另行部署的服务器。完成第一位管理员后，在网页客户端的「设置 → 服务器与账户」填写该服务器地址。

## 更新已有服务器

更新的是程序。不要删掉或重新生成 `.env` 里已经在用的四把密钥，也不要删 `data/openlogtool.db`。更换密钥后，现有登录、邀请码或 Live Share 链接会失效。

### Docker 一键安装

再次执行原来的命令。脚本会快进 `main`、构建、备份已有数据库，并保留原来的 `.env`：

```
curl --proto '=https' --tlsv1.2 -fsSL \
  https://raw.githubusercontent.com/Mazha0309/CallsignRollLogServer/main/deploy-docker.sh \
  | bash -s -- 3000
```

当初使用的端口不是 3000 时，此处仍填写该端口。备份在 `~/OpenLogToolServer-backups/<时间>/`。

### 自行维护的 Docker

在仓库目录。先构建，构建成功后再停、再备份、再启动。不要先删除容器和 `data`：

```
git fetch origin main
git switch main
git pull --ff-only origin main
docker compose build server
docker compose stop server
cp -a data "data-backup-$(date +%Y%m%d-%H%M%S)"
docker compose up -d --force-recreate server
docker compose ps
curl -fsS http://127.0.0.1:3000/api/v1/server-info
```

`.env` 里如果改过 `HOST_PORT`，最后那条检查也要改成该端口。数据库迁移在新进程启动时自动做。不要同时跑两个进程打开同一个 `data/openlogtool.db`。

只改了环境变量、代码没变：不必重新构建镜像，执行 `docker compose up -d --force-recreate server`。

### 原生 Node.js 或 PM2

先把 `./data` 复制一份到仓库外面。再执行原来的一键部署命令。生产环境使用 `main`。`dev` 只用于试验，不要把正在提供服务的服务器切换到 `dev`。

### 无法完成

- `git pull --ff-only` 拒绝：本地有分叉或未提交的已跟踪修改。先处理这些修改。不要用 `reset --hard` 丢弃 `.env`。`.env` 通常未被跟踪，但不要执行 `git clean`。
- 新进程无法启动，且旧进程已经停止：用刚复制备份的 `data-backup-...` 或 `~/OpenLogToolServer-backups/` 恢复 `data`，再启动上一版可用的镜像。不要为了启动而更换密钥。
- 更新后所有人需要重新登录，且邀请码失效：密钥已被重新生成。恢复旧 `.env` 并重启。没有旧文件时，这些链接无法恢复。

## 前面加 HTTPS

向他人提供访问时，在服务器前面加一层 HTTPS 反向代理。成员用 `https://log.example.com` 这种地址。除了浏览器承认的本机地址，不要用明文 HTTP 登录门户或后台。

服务器进程继续只听本机，例如 `127.0.0.1:3000`。对外的 443 由 Caddy、Nginx 或其他代理来做证书。

### 可信代理

只有一层可信代理时，在 `.env` 里写：

```
TRUST_PROXY=1
```

或者在管理后台「服务器设置 → 可信代理层数」填 `1`。后台保存的值优先于 `.env`。两种都要在改完后重启进程。Docker 是 `docker compose up -d --force-recreate server`，不是只改文件。

不要在 Node 端口可被直接访问时把 `TRUST_PROXY` 设为 `true`。填实际的层数。端口继续只绑在本机，或放在防火墙后面。

### 转发路径

至少把这些转到这台服务器：

- `/api`：登录、注册、协作接口。
- `/ws`：协作的实时连接。要允许 HTTP/1.1 的 WebSocket Upgrade。没开 Upgrade 时，页面能开，实时内容不会更新。
- `/live`：Live Share 页面。
- 用了网页客户端时，再加上 `/client/` 和 `/connect`。
- 公开归档如果做了根路径别名，那个别名路径也要原样转发，不能被其他站点规则拦截。

示例在服务端仓库的 `deploy/nginx-openlogtool.conf.example`。按实际域名修改 `server_name` 和证书路径。

### Live Share 持续重连

在浏览器的网络面板里看 `/ws/public`：

- `403`：通常是 `TRUST_PROXY`、`Host` 或 `X-Forwarded-Proto`。代理要带上原始的 Host，以及 `X-Forwarded-Proto https`。层数要和真实的代理层数一致。
- `404`、`200` 或 `502`：通常是未把 `/ws` 转到 Node，或没打开 Upgrade。普通网页的反代规则不够。

### 完成后

用域名打开 `https://log.example.com/login`。地址栏应显示安全连接，而不是证书错误。登录后可以打开好友页。已发布的 Live Share 可在其他浏览器打开，且不会停留在正在重连。

## 配置

客户端里能改的，在「设置」。服务器上能改的，在 `.env` 或管理后台。改完 `.env` 要重启进程才生效。后台里已经保存的同一项，优先于 `.env`。

### 客户端地址

「设置 → 服务器与账户」。页面标题为「服务器与账户」。地址填服务器的根，例如 `https://log.example.com`。不要填成 `/api/v1` 或其他接口路径。

服务器 `/connect` 页上的地址和二维码用于此处。整段粘贴 `/connect`、`/client/` 或门户链接也可以，软件会取出根地址。扫到或粘贴出一个和当前不同的地址时，会先说明要换成哪一台。取消则保持原来的服务器和登录状态。

填写地址后点击「确认地址并连接」。需要账号时再点击「登录」或「注册」。仅填写地址不会登录。

### 公开注册

管理后台 → 服务器设置 →「允许公开注册」。

关掉之后，客户端的「注册」和网页的 `/register` 都会失败。已经有的账号仍能登录。管理员仍可在后台创建账号。空库的第一位管理员不由该开关产生，而由 `/bootstrap` 产生，见[第一个管理员](#第一个管理员)。新安装默认允许。

### 环境变量

常用的这些。完整表在服务端仓库 README 的「环境变量」。

| 变量 | 用途 |
| --- | --- |
| `PORT` | Node 监听的端口，默认 3000。改了之后，健康检查和反代的上游都要改成同一个端口。 |
| `HOST_PORT` | 只在 Docker 里。发布到宿主机的端口。容器里面仍是 3000。 |
| `BIND_ADDRESS` | 默认只给本机。仅在需要局域网直接连接该端口时修改。公网优先使用反向代理，不要绑定到所有网卡。 |
| `DB_PATH` | SQLite 文件，默认 `./data/openlogtool.db`。更换路径前先停止进程，并将原文件复制到新路径。 |
| `JWT_SECRET` | 登录密钥，至少 32 字节。装好之后不要换。 |
| `ADMIN_BOOTSTRAP_TOKEN` | 空库创建第一个管理员，至少 24 字节。不是日常密码。 |
| `INVITE_HMAC_KEY` | 邀请码密钥，至少 32 字节，不能和登录密钥相同。换了之后，旧邀请码失效。 |
| `PUBLIC_SHARE_HMAC_KEY` | 公开页密钥，至少 32 字节，须独立设置。换了之后，已经发出的 Live Share 链接失效。 |
| `CORS_ORIGINS` | 允许的网页客户端来源，逗号分隔。原生客户端不用填。见下一节。 |
| `TRUST_PROXY` | 前面有几层可信代理。默认不信任。见[前面加 HTTPS](#前面加 HTTPS)。 |
| `WEB_CLIENT_DIR` | 网页客户端文件的位置，默认同目录的 `./web-client`。一般不用改，除非构建产物不在默认目录。 |

四个密钥升级时不要换。在线备份是整份数据库，含密码哈希，不包含 `.env`。更换机器时，数据库和 `.env` 都要保留。

### 网页和服务器不同源

原生客户端不受浏览器跨域限制。网页客户端如果和服务器的协议、域名或端口不同，服务器要写网页客户端的完整来源，不是写 API 自己的地址。例如网页在 `https://log.example.com`，服务器在另一台：

```
CORS_ORIGINS=https://log.example.com
```

多个来源用逗号分隔，不要写成 `*`。改完后重建或重启服务器。挂在同一台服务器的 `/client/` 上、并且反代保留了所需响应头时，不用另填。

网页客户端还要求 HTTPS（或浏览器承认的 localhost），以及响应头 `Cross-Origin-Opener-Policy: same-origin` 和 `Cross-Origin-Embedder-Policy: credentialless`。和服务器放在一起时，由服务器加上。单独部署时，仓库里的 Nginx 镜像已经带上。自行编写反向代理时须带上这两行。缺少时页面可以打开，但本机库无法初始化。

### AI 语音

默认关闭，在「设置 → AI 辅助」。这一类里有「AI 辅助识别」和「文字助手」，各自开关，互不影响。

语音：音频直接发给所配置的服务，不经过协作服务器。识别结果只是候选，不会自动保存，也不会自动填时间和主控呼号。接口填写方式见客户端仓库的 `docs/ai-speech-recognition.md`。

文字助手：只对词库和字段格式提建议。确认之前不修改词库，也不修改已有记录。密钥放在这台设备的安全存储里，不会写进普通设置或导出文件。

服务器上的 Excel 校对是另一件事：管理员在后台「服务器设置 → 服务端 LLM」填写，所有者或可编辑成员在门户的记录页使用。模型不能直接写数据库，每一条都须人工确认。

### 其他设置

- **外观**：主题色、深色模式、字体、界面语言。改完立即生效。界面缩放只留在这台设备上。
- **工作台**：标题是「点名台与布局」。「呼号历史一键复用」打开后，呼号栏可以根据本机以往记录填设备、天线、QTH、功率和高度。还有重复呼号提醒、表格分页。
- **主控屏**：场内显示。不是 Live Share。
- **应用**：关于、许可、诊断日志，以及「恢复默认设置」。恢复默认不会删点名记录。

## 继续开发

本页说明代码位置和验证命令。某个按钮的现行行为以软件和本手册为准。`docs/superpowers/` 是某次功能的设计和施工记录，不是现行说明书。和代码不一致时，以代码、测试和 `*-api-v1.md` 为准。

不要把签名私钥、keystore 口令、API 密钥写进仓库、文档或测试。不要为了查看效果而修改生产数据库，也不要使用真实账号登录生产服务器做试验。

### 客户端

仓库是 [Mazha0309/CallsignRollLog](https://github.com/Mazha0309/CallsignRollLog)。界面在 `lib/`，本机数据库在 `rust/`。文案在 `lib/l10n/` 的 ARB 里。`lib/l10n/generated/` 不要手工修改，修改 ARB 后生成。

```
git clone https://github.com/Mazha0309/CallsignRollLog.git
cd CallsignRollLog
flutter pub get
```

需要 Flutter 3.44+、Dart 3.12+、Rust 1.91.1（`rust-toolchain.toml` 会固定）。Linux 构建还要 `libsecret-1-dev`。各平台的打包命令、Web 构建依赖和版本号工具在仓库 README。修改范围和提交前的检查见 `docs/development.md`。

改界面文案时，四个 ARB 一起改：`app_zh.arb`、`app_zh_CN.arb`、`app_en.arb`、`app_en_US.arb`。然后：

```
flutter gen-l10n
```

先运行本次修改对应的测试，不必一开始运行全部测试：

```
flutter test test/providers/account_share_dictionary_test.dart
flutter analyze
```

将路径换成本次修改对应的测试。Rust 侧在 `rust/` 目录执行 `cargo test`。ARB 和生成文件一起提交。

### 服务端

仓库是 [Mazha0309/CallsignRollLogServer](https://github.com/Mazha0309/CallsignRollLogServer)。HTTP 在 `src/api/`，成员门户在 `web/`，公开 Live Share 在 `live/`。迁移全在 `src/db/migrations.ts`。已发布的迁移正文不要修改。需要改表时新增一份迁移。

```
git clone https://github.com/Mazha0309/CallsignRollLogServer.git
cd CallsignRollLogServer
cp .env.example .env
npm ci
(cd web && npm ci)
(cd live && npm ci)
npm run dev
```

需要 Node.js 24.18+ 和 npm 10+。`.env` 按[开始之前](#开始之前)的四把密钥填。空库还要能按[第一个管理员](#第一个管理员)创建管理员。`npm run dev` 仅用于本机，不要指向生产数据库。

提交前，先跑和这次改动对应的检查：

```
npm run typecheck
npx tsx --test test/某份测试.test.ts
```

整次验证用 `npm run verify`。该命令耗时较长，且不使用仓库中的生产数据库。目录、迁移规则和测试写法在 `docs/development.md`。某个接口的字段和错误码在同目录的 `*-api-v1.md`，不要复制进这份使用手册。

实时连接和限流都在一个 Node 进程的内存里。不要为了能跑而开多个副本去分担同一份库。两个进程同时打开同一个 `data/openlogtool.db` 会坏。

记录客户端的源码不在这个仓库。改完客户端后，用[网页客户端](#网页客户端)里「和服务器放在一起」的命令装进 `web-client/`，再重启服务器，`/client/` 才是新的那一版。
